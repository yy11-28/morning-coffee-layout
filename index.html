01 · 布局核心概念

页面布局的本质：结构、对齐与留白

本章项目预告：本章我们不再零散地学属性，而是从头到尾做一个真实页面——「晨光咖啡」咖啡店落地页。它包含顶部导航栏、Hero 横幅（标题+主图+点单按钮）、特色介绍卡片行、产品菜单九宫格、购物车角标、页脚，并且要在手机、平板、电脑上都好看。每一节我们都只完成这个页面的一个模块，九节之后拼起来就是一个完整网站。

本节自学目标：

  1. 理解布局的本质：结构、空间和层级决定阅读效率
  2. 掌握页面排版的四大基础原则：结构、对齐、留白、层级
  3. 看懂「晨光咖啡」整页蓝图，知道每个模块将来用什么布局技术实现
  4. 建立“先结构后样式、先内容后装饰”的布局思路

正文

假设店长只给了我们一段需求文字：“我要一个咖啡店网页，上面能看到店名和导航，中间有大图吸引顾客，下面展示几款招牌咖啡，顾客能点单，手机也要能看。”布局要做的第一件事，不是打开编辑器写 CSS，而是把这段话拆成有层级的页面模块。

一、把「晨光咖啡」拆成页面模块（结构优先）

按照信息重要程度，整页从上到下分为 6 个区块：

  1. 顶部导航 header：Logo「晨光咖啡」+ 菜单链接（首页/菜单/门店/关于）+「立即点单」按钮——这是全站入口，最重要。
  2. Hero 横幅 section：一句宣传语 + 一张咖啡大图 + 一个点单按钮，是首屏视觉焦点。
  3. 特色介绍 section：3 张卡片（现磨豆源 / 30 分钟送达 / 会员优惠）并排。
  4. 产品菜单 section：6~9 款咖啡以规整九宫格展示，每款有图、名称、价格、加购按钮。
  5. 悬浮元素：购物车图标上的数量红色角标、右下角「回到顶部」按钮。
  6. 页脚 footer：营业时间、地址、联系方式等多列信息。

这一步只写 HTML 语义结构（header / section / footer），一行 CSS 都不写。先有内容逻辑，再有视觉表现——这就是结构优先。

二、四大排版原则在咖啡店页面里的样子

  1. 结构优先：视觉顺序与顾客阅读顺序一致——先看到店名，再看卖点，最后看菜单下单。
  2. 对齐统一：导航、横幅、卡片、页脚共用同一条左右边界，价格、按钮在卡片内统一对齐。
  3. 留白控制：区块之间留白大（分组），卡片内部留白小（成组），页面才有呼吸感。
  4. 层级表达：Hero 宣传语最大最深（主标题）、菜单名次之（正文）、价格说明最浅（辅助），层级控制在 3 级内。

三、九节学习路线：同一家店，逐个模块攻克

  • 第 2 节 盒模型：搞清点单按钮为什么有大有小、卡片内边距怎么算。
  • 第 3 节 文档流：不写布局 CSS 时，咖啡店各区块默认怎样从上往下堆。
  • 第 4 节 定位：做吸顶导航、购物车角标、回到顶部按钮。
  • 第 5 节 Flex（一维）：做顶部导航栏、3 张特色卡片横排。
  • 第 6 节 Grid（二维）：做产品菜单九宫格、焦点大卡片。
  • 第 7 节 响应式：让同一页在手机变单列、电脑变多列。
  • 第 8 节 视觉细节：统一间距、字体层级、圆角阴影、按钮 hover，让页面有质感。
  • 第 9 节 综合实战：把所有模块拼装成完整的「晨光咖啡」页面。

关键认知：布局不是“把元素摆好”，而是“让信息有顺序、有层级、有呼吸”。后面每学一个技术，都要先问自己：它解决的是咖啡店页面哪个模块的问题？

02 · CSS 盒模型

盒模型决定元素的尺寸与间距

项目进度：上一节我们把「晨光咖啡」页面拆成了导航、Hero、特色卡片、菜单九宫格等模块。但在排列它们之前，先要搞懂一件事：页面里每个元素本质上都是一个矩形盒子。为什么点单按钮里文字不会贴边？为什么卡片之间能留出空隙？答案都在盒模型里。

本节自学目标：

  1. 认识 CSS 盒模型 4 个组成区域：content、padding、border、margin
  2. 结合点单按钮、菜单卡片分清 padding 和 margin 的作用与差异
  3. 理解 box-sizing 两种模式，掌握盒子宽度计算公式
  4. 了解 margin 特殊特性：外边距塌陷、负值

正文

打开「晨光咖啡」页面，导航链接、立即点单按钮、每一张咖啡卡片、甚至整张 Hero 横幅——浏览器全部把它们当作矩形盒子来摆放。学会计算这些盒子的尺寸和距离，才能精准控制页面。

一个完整盒子由 4 层构成，从内向外依次是：

1. content（内容区）——按钮文字、卡片里的咖啡名

存放真实内容：比如点单按钮上的“立即点单”四个字、菜单卡片里的拿铁图片与价格。默认情况下，width / height 只作用于 content 内容区。

2. padding（内边距）——让按钮文字不贴边

内容与边框之间的内部空白。给点单按钮设置 padding: 12px 28px，文字四周就有了呼吸空间，按钮自然变大、更易点击；菜单卡片用 padding: 16px 让图片文字不顶到卡片边缘。padding 属于盒子本身、会占尺寸，不能为负值。

3. border（边框）——卡片的描边

盒子的边界线，比如菜单卡片 1px 的浅灰描边。边框本身也占尺寸，会影响盒子最终可见宽高。

4. margin（外边距）——卡片与卡片之间的距离

当前盒子与其他盒子之间的外部距离。导航链接之间、特色卡片之间、区块与区块之间靠 margin（或后面学的 gap）拉开。margin 不属于盒子本体，支持负值。注意：上下两个块级元素的垂直 margin 会发生外边距塌陷（取最大值而非相加），水平方向不会塌陷。

用一个点单按钮算笔账（box-sizing）

假设我们要求点单按钮视觉宽度正好 140px：

  • content-box（默认）：width: 100px 只给内容区，再加左右 padding 各 15px、边框 5px，按钮实际宽 = 100 + 30 + 10 = 140px，要自己做加法。
  • border-box：直接写 width: 140px; padding: 0 15px; border: 5px，这 140px 已经包含 padding 和 border，写多少就是多宽。做整页卡片网格时，border-box 不会让卡片因内边距而撑破行列，项目开发推荐统一使用。

回到咖啡店页面

本节结束，我们的素材库里每个模块都有了正确的“盒子尺寸”：按钮有舒适的 padding、卡片有统一的内边距和描边、模块之间有 margin。下一节将看到：在还不学 Flex/Grid 时，这些盒子默认会怎样在页面里从上往下流动排布。

⚠️ 关键认知：盒模型决定了“元素从哪里开始，到哪里结束”。布局错位、间距算不对，十有八九是盒模型没算清。

03 · 文本流布局

默认文档流：块级、行内与图文自然分布

项目进度：我们已经给「晨光咖啡」的按钮、卡片设好了盒模型尺寸。现在把所有模块的 HTML 写好、先不写任何 Flex/Grid/定位代码，直接在浏览器打开——会看到什么？导航、横幅、卡片全部老老实实从上往下排成一竖列。这就是浏览器自带的默认文档流，也是所有布局的起点。

本节自学目标：

  1. 理解什么是浏览器默认文档流，能预测咖啡店页面“裸奔”时的样子
  2. 区分块级元素、行内元素的布局行为
  3. 掌握文本流下图文混排的特点与坑点（图片底缝、浮动）
  4. 知道文档流能做什么、不能做什么，为第 4、5 节的定位和 Flex 埋下需求

正文

文档流是浏览器默认的元素排列规则：元素按 HTML 书写顺序，从上到下、从左到右依次排布。把咖啡店页面裸跑一遍，你会发现：header 独占最上面一整条，Hero 横幅在它下面再占一整条，特色卡片、菜单区、页脚依次垂直堆叠——但导航里的 4 个链接却在同一行横着排。为什么？因为元素分两类。

一、块级元素：独占一行的“整行区块”

代表标签：div、p、h1~h6、ul、ol，以及我们用的 header、section、footer。

  • 独占新一行，宽度默认撑满父容器——所以每个大区块上下堆叠、自动占满页面宽度；
  • 可以正常设置 width、height、padding、margin；
  • 咖啡店页面的 6 大区块都是块级，天然完成了“上下分区”。

二、行内元素：挤在一行的“文字部件”

代表标签：span、a、strong、em。

  • 不独占一行，沿文字基线横向排列——所以导航的 4 个 <a> 链接天然横排；
  • 上下 margin、width、height 默认不生效，只能调水平间距；
  • 所以光靠默认流，导航链接能横排，但无法让 Logo 在左、链接居中、点单按钮在右——这正是第 5 节 Flex 要解决的。

💡 自学提示：行内与块级可以用 display 互相转换，比如给链接 display: inline-block 就能给它设上下 padding，做出可点击的大按钮。

三、图文混排：菜单卡片里的图片底缝

<img> 是特殊的行内块元素，默认按文本基线对齐，直接放进卡片底部会出现一条几像素的小缝隙——这是新手做菜单卡片最常见的坑，给图片设 display: block 即可消除。若要“文字环绕图片”，老办法是 float 浮动，但浮动会造成父元素高度塌陷，现代开发中横向排列一律交给后面的 Flex/Grid。

四、文档流的能力边界（引出后续章节）

默认流能让页面“从上到下有顺序”，但对咖啡店页面来说它做不到：

  1. 让导航栏滚走后仍吸在顶部、购物车角标压在图标右上角——需要第 4 节定位；
  2. 让 3 张特色卡片横向并排、等高均分——需要第 5 节 Flex；
  3. 让 9 款咖啡排成规整九宫格、焦点款跨两列——需要第 6 节 Grid。

⚠️ 关键认知：真实页面是组合拳——大区块靠文档流上下堆叠，区块内部的横向/网格排列再交给 Flex、Grid。先认清默认行为，才知道什么时候需要打破它。

04 · Position 定位

定位与层叠：控制元素的相对位置与视觉层次

项目进度：上一节我们看到，咖啡店页面在默认文档流下只能老老实实地从上往下堆。但有三个需求默认流做不到：① 顾客往下翻菜单时，顶部导航要一直吸在屏幕顶端；② 购物车图标右上角要压一个红色数量角标；③ 右下角要放一个始终悬浮的「回到顶部」按钮。这三个需求，都要用 position 定位来实现。

本节学习目标

  1. 理解定位的核心作用：脱离文档流、重构元素位置、控制视觉层级
  2. 结合吸顶导航、购物车角标、回到顶部，掌握各定位模式的参照物与场景
  3. 弄懂 relative、absolute、fixed 的核心区别与高频误区
  4. 掌握 z-index 生效条件与层叠优先级规则

正文

默认文档流里元素互相占位、互不重叠。而 position 定位是 CSS 用来打破文档流的能力：让元素脱离常规排版、自由摆放，并建立视觉层级。学定位始终看三件事：参照物是谁、是否脱离文档流（还占不占位）、能不能用 z-index。

1. static 默认定位（咖啡店所有区块的初始状态）

所有元素默认 static：遵循正常文档流，不能用 top/left，z-index 无效。导航、横幅、卡片在没加定位前都是这个状态，不用手动写。

2. relative 相对定位（给购物车图标“定位锚点”）

参照物是元素自身原位置，不脱离文档流（原来的位置保留）。它在咖啡店里最重要的用途不是挪元素，而是：给购物车按钮加 position: relative，让里面的红色角标以它为基准定位。这就是经典的「父 relative + 子 absolute」组合里父级的角色。

自学重点误区：relative 不是用来做大布局移动的，主要作用是留占位 + 充当定位父级。

3. absolute 绝对定位（购物车红色角标）

参照物：最近一个非 static 的祖先；完全脱离文档流，不占位、漂浮在普通内容之上。给角标写 position: absolute; top: -8px; right: -8px，它就精准贴在购物车图标的右上角；因为父级按钮已经是 relative，角标不会跑偏到整个页面。若所有祖先都是 static，它才会改为相对浏览器视口定位。

核心概念：定位包含块——absolute 能否定位准确，完全取决于有没有一个 relative/fixed 的父级。Hero 横幅上“今日特惠”标签压在图片一角，用的也是同一套写法。

4. fixed 固定定位（吸顶导航 + 回到顶部）

参照物是浏览器视口，完全脱离文档流，页面滚动时永远固定在屏幕上不动。给顶部导航 position: fixed; top: 0; left: 0; right: 0，顾客浏览长菜单时导航始终可用；右下角「回到顶部」设 right: 24px; bottom: 24px 同样用 fixed。注意：fixed 元素脱流后不再占位置，要给下方内容补 padding-top，否则开头内容会被导航盖住。

5. z-index：控制谁压在谁上面

元素重叠时用 z-index 控制上下顺序，前提是元素必须先设置非 static 定位。值越大越靠前。咖啡店页面通常这样分层：导航/回到顶部 z-index 最高（如 100），角标、标签压在各自父级之上，普通内容保持默认。切忌一上来就写 9999——层级是相对各自层叠上下文比较的，乱写会导致弹窗被遮挡等疑难问题。

✅ 四种定位在咖啡店页面里的分工（自学必背）

  1. static：正常流、无偏移（所有普通区块）
  2. relative：相对自己、留占位、做角标的定位父级
  3. absolute：相对定位父级、漂浮叠加（购物车角标、横幅标签）
  4. fixed：相对屏幕、固定不动（吸顶导航、回到顶部）

📌 关键认知：普通流负责“排版”，定位负责“叠加”。定位只解决少数悬浮/覆盖元素，绝不能拿它来排整个页面——咖啡店的主体排布，接下来交给第 5 节的 Flex。

05 · Flex 布局

一维布局：让组件、按钮和导航按比例分布

项目进度：定位解决了吸顶导航和购物车角标，但咖啡店导航栏内部还是“挤成一堆”：我们想要 Logo 在最左、菜单链接居中、立即点单按钮在最右，下方的 3 张特色卡片也要横向并排、等高、间距均匀。这些“同一行/同一列上的一维排布”，正是 Flex 布局最擅长的事。

本节自学目标：

  1. 理解 Flex 布局的核心本质：解决一维自适应排列问题
  2. 掌握主轴、侧轴的动态对应关系，读懂 Flex 所有对齐规则
  3. 结合导航栏、特色卡片行熟练掌握主轴对齐、侧轴对齐、自动换行、间距控制
  4. 区分 Flex 与文档流、定位、Grid 的适用差异
  5. 规避 Flex 常见挤压、不换行、对不齐的坑点

正文

一、Flex 核心本质：一条线上的智能排布

Flex 让一组子元素在横向或纵向单一方向上自动排列、对齐、均分、换行。给导航容器加 display: flex，Logo、链接、按钮立刻变成一行；给特色卡片区加 Flex，3 张卡片自动横排并均分宽度，无需浮动、不用逐个算 margin。

二、主轴与侧轴：先分清方向再谈对齐

  • 主轴：子元素排列方向，默认横向（row）——导航栏就是横向主轴；
  • 侧轴：垂直于主轴的方向，默认纵向——控制一行元素的高低对齐；
  • 改成 flex-direction: column 后两轴互换，比如页脚里竖着排列的“营业时间 / 地址 / 电话”。

💡 自学关键：所有对齐属性先看当前主轴是横向还是纵向，否则 justify-content、align-items 一定会记混。

三、四大核心属性在咖啡店页面里的用法

1. justify-content —— 主轴对齐（导航怎么分布）

  • space-between：导航栏首选——Logo 贴最左、点单按钮贴最右、链接在中间自动均分；
  • center：Hero 区把点单按钮居中；
  • flex-start / flex-end：靠左 / 靠右排列；space-around：每个元素两侧等距。

2. align-items —— 侧轴对齐（高低对齐）

导航栏里 Logo 是图标、链接是文字、按钮更高，用 align-items: center 让它们垂直居中在一条基线上；特色卡片文字多少不同，用 stretch（默认）让一行卡片等高，页面更整齐。

3. flex-wrap —— 空间不够时换不换行

默认 nowrap：窗口变窄时，导航链接和特色卡片会被强行压缩变形。给特色卡片行加 flex-wrap: wrap，窄屏时卡片自动掉到下一行，不挤压（第 7 节响应式会大量用到）。

4. gap —— 统一间距

导航链接之间 gap: 24px、特色卡片之间 gap: 20px，一处设置、间距统一，不会像 margin 那样在首尾多出边距。

四、Flex 适用场景（自学必记）

  • ✅ 顶部导航栏、按钮组、标签行、卡片内部的“图标+文字”
  • ✅ 特色卡片横排、页脚信息列、需要垂直居中的场景
  • ❌ 产品菜单那种同时控制多行多列的九宫格——下一节交给 Grid。

五、自学高频误区

  1. 不看主轴方向就套对齐属性，效果和预期相反；
  2. 忘了 flex-wrap: wrap，窄屏下卡片被压扁；
  3. 用 margin 逐个控制间距，首尾留白错乱，应优先用 gap；
  4. 拿 Flex 硬做二维九宫格，疯狂嵌套——那是 Grid 的主场。

06 · Grid 布局

二维布局：网格让页面更稳定、更有秩序

项目进度：上一节用 Flex 排好了导航和 3 张特色卡片。现在轮到咖啡店的核心模块——产品菜单区：6 款咖啡要排成整齐的多行多列，每列等宽、间距统一，本周主推款还要占两格做成大卡片。这种同时控制行和列的二维排布，正是 Grid 网格布局的主场。

本节自学目标：

  1. 理解 Grid 与 Flex 的核心区别：二维网格排布 vs 一维弹性排布
  2. 结合产品菜单掌握网格轨道、比例单位 fr、行列定义
  3. 学会用跨列能力把“本周主推”做成焦点大卡片
  4. 掌握网格 gap 间距规则，让菜单矩阵整齐统一
  5. 明确 Grid 专属场景，避免 Flex、Grid 混用错乱

正文

一、Grid 核心本质：先划网格，再放咖啡

Flex 的逻辑是元素沿一条线流动；Grid 的逻辑是容器先划分好行和列的网格，元素再依次落入格子。给菜单容器 display: grid 并定义 3 列，6 款咖啡就自动排成 2 行 × 3 列，窗口缩放时各列同步伸缩，永远整齐。

二、网格轨道与 fr：菜单列宽怎么定

grid-template-columns 定义列轨道，宽度可以写像素、百分比，或 Grid 专属比例单位 fr：

  • repeat(3, 1fr)：菜单 3 列等宽，剩余空间平均分配——最常用；
  • 2fr 1fr 1fr：第一列（比如“套餐推荐”栏）占两份宽，形成主次布局；
  • 200px 1fr 1fr：左侧固定 200px 放分类筛选，右侧产品自适应——后台/点单页常见框架；
  • minmax(240px, 1fr)：列宽不低于 240px，配合 auto-fit 可在窄屏自动少一列。

fr 按比例分配扣除固定宽和 gap 之后的剩余空间，不会挤压溢出，是自适应菜单矩阵的最佳选择；只会写死像素，窗口一变就会留白或撑破。

三、本周主推：跨列与统一间距

给第一张“本周主推·招牌拿铁”卡片加 grid-column: 1 / span 2，它从第 1 条网格线起横跨两列，立刻成为视觉焦点，后面的美式、卡布奇诺自动补位——这就是 Grid 制造页面层级的能力，Flex 很难在二维上直接做到。行列间距统一用 gap: 16px，相比逐个写 margin，第一行和最后一行外侧不会多出边距，菜单四周整齐对齐。

四、Grid 适用场景（自学必记）

  • ✅ 产品菜单九宫格、图片图库、首页多列框架、数据看板
  • ✅ 需要跨行跨列、有焦点区块的图文混排
  • ❌ 顶部导航、按钮组这种一维排列——用 Flex 更简单，不要为了用 Grid 而嵌套多余结构

五、自学高频误区

  1. 导航栏、按钮组也硬套 Grid，结构冗余——一维交给 Flex；
  2. 列宽只会写死像素，不会用 fr，屏幕变化就溢出或留白；
  3. 用 margin 逐个控制卡片间距，导致菜单边缘对不齐——用 gap；
  4. 不会跨列跨行，把主推款和普通款做成一样大，浪费了 Grid 的层级能力。

07 · 响应式布局

屏幕尺寸变化时，布局也要保持稳定与适配

  1. 理解响应式核心：不是堆样式，而是同一套内容在多端保持可读可用
  2. 掌握移动端优先与优雅降级两种思路的差异
  3. 读懂 @media 断点，会写咖啡店页面单列 → 双列 → 多列的切换
  4. 熟练使用 rem、vw、vh 让文字、Hero 大图随屏缩放
  5. 守住底线：小屏不溢出、点单按钮不丢失、菜单始终可读

正文

一、咖啡店页面在三端应该长什么样

  • 手机（≤768px）：导航折叠为 Logo+点单按钮、特色卡片单列、菜单九宫格降为单列或双列、Hero 字号变小——保证拇指能点、文字能读；
  • 平板（769~1023px）：特色卡片恢复 3 列、菜单变 2~3 列；
  • 桌面（≥1024px）：完整多列网格、最大间距、横幅占满视口宽度。

终极原则：页面不崩溃、内容不挤压、核心功能（看菜单、点单）不丢失。

二、移动端优先：先做好手机上的咖啡店

推荐用 Mobile First：默认样式就是手机版（单列、小间距），再用 @media (min-width: 769px) 逐步为平板、桌面“增强”成多列。反过来“先做桌面再压缩到手机”（优雅降级）很容易出现按钮挤爆、菜单溢出——配套 Demo 里可以直接对比这两种策略在 375px 下的差异。

三、@media 断点：菜单列数的开关

断点就是屏幕宽度阈值。菜单区的经典写法：

  • 默认（手机）：grid-template-columns: 1fr 单列；
  • @media (min-width: 769px)：升级为 repeat(2, 1fr)；
  • @media (min-width: 1024px)：升级为 repeat(3/4, 1fr) 完整网格。

前提：HTML 的 <meta name="viewport" content="width=device-width, initial-scale=1"> 必须声明，否则手机会按桌面宽度缩小整个页面，媒体查询全部失效。

四、rem 与 vw / vh：让尺寸随屏缩放

  • rem：相对 <html> 根字号。配合断点把根字号从 14px 调到 16px，菜单名、价格、间距整体等比缩放，不用逐个改；
  • vw / vh：1vw 等于视口宽度的 1%。Hero 横幅用 height: 40vh、宽度 100%，在任何屏幕上都保持舒适比例；
  • 固定 px 写死四列卡片，手机上必然横向溢出——Demo 的“固定 px”模式会直接演示这条滚动条。

五、自学高频误区

  1. 以为响应式要为每种屏幕重写一套页面——核心只是断点处调整布局；
  2. 尺寸全写死 px，小屏溢出裁切；
  3. 先做桌面再逆向适配，小屏错乱难补救；
  4. 断点处只改列数、不改字号间距，临界尺寸下比例突兀。

间距、对齐、层级与颜色：决定页面是否“高级”

项目进度：经过前七节，「晨光咖啡」页面功能已经齐全、三端都能适配，但看起来还像一份“能用的作业”而不是“想下单的店”。最后一步是视觉收尾：统一间距、做出字体层级、给菜单卡片加圆角阴影、给点单按钮加 hover 反馈——布局决定骨架，细节决定气质，这一节让页面从“整齐”变成“有质感、值得信任”。

本节自学目标：

  1. 理解视觉细节不是装饰，而是规范、层级、秩序感的体现
  2. 掌握间距、字体、圆角阴影、对齐四大规范在咖啡店页面的落地
  3. 学会用三层字体层级区分咖啡名、描述、价格
  4. 掌握点单按钮 hover / active 交互反馈规则
  5. 规避随意调数值、无层级、乱圆角等新手误区

正文

一、间距系统：给咖啡店页面统一“呼吸节奏”

新手最大的通病是每个间距都凭感觉写 13px、17px、22px。专业做法是采用 8px 基准体系：菜单卡片内边距 16px、卡片间距 16/24px、区块间距 32px，全部取 8 的倍数。导航到 Hero、Hero 到菜单、菜单到页脚的留白节奏一致，页面立刻显得规整。

二、字体三层级：让顾客一眼找到重点

  • 主标题：Hero 宣传语最大最粗最深，承担分区作用；
  • 正文：咖啡名称、介绍文字字号适中、可读性最强；
  • 辅助：价格备注、“月售 320 杯”这类信息字号偏小、颜色偏浅。

层级的本质是用样式区分信息重要程度——所有文字一样大，顾客就抓不住“该看咖啡名还是该看价格”。

三、统一圆角与柔和阴影：菜单卡片的质感来源

  • 圆角：菜单卡片、点单按钮、输入框统一同一套圆角（如卡片 12px、按钮 999px 胶囊形），不要每张卡片弧度不同；圆角让页面更柔和、现代、有亲和力；
  • 阴影：卡片用轻量、低透明度的柔和阴影做出悬浮分层，hover 时阴影略微加深；切忌厚重发黑的投影。

四、对齐：成本最低的专业感

所有卡片左边界对齐、卡片内图片与文字左对齐、价格与加购按钮在卡片底部统一对齐。参差一个像素，页面就显得粗糙。配合 Grid/Flex，对齐几乎是自动完成的——这也是前面布局技术的价值。

五、交互反馈：让点单按钮“会回应”

  • hover：按钮轻微变色、上浮 1~2px、浅阴影浮现，告诉顾客“我可以点”；
  • active：按下时轻微缩小、颜色加深，反馈“点单成功”的触感；

变化要柔和轻微（配合 transition），不突兀。导航链接、菜单卡片、加购按钮都应有状态反馈。

六、自学高频误区

  1. 间距随手写数值，整页没有统一节奏——用 8px 倍数；
  2. 所有文字一样大，页面扁平无重点——建三层级；
  3. 圆角阴影每张卡片不一样、阴影又黑又重；
  4. 按钮没有 hover/active，页面像一张不能点的图片；
  5. 一味堆特效，反而破坏对齐和秩序——高级感来自规范统一，不是装饰多。

09 · 综合实战案例

把布局原则落地到真实页面：从结构到细节的完整闭环

项目进度：恭喜，「晨光咖啡」落地页的所有零件已经全部做完了——第二节做好了点单按钮的盒模型，第三节理清了整页文档流，第四节实现了吸顶导航、购物车角标和回到顶部，第五节用 Flex 排好了导航和特色卡，第六节用 Grid 铺好了产品菜单，第七节完成三端适配，第八节统一了质感。本节只有一件事：把它们按正确顺序组装成完整网页，顺便建立以后做任何页面都通用的开发流程。

本节自学目标：

  1. 掌握「先结构、再布局、后视觉」的标准开发流程，告别边写边调
  2. 能说清晨光咖啡页每个模块为什么选文档流 / 定位 / Flex / Grid
  3. 理解先可读性后美观、先刚需后装饰的取舍原则
  4. 能把这套流程迁移到一个全新主题的页面上

正文

一、回顾：九节课如何拼出晨光咖啡页

  • 结构：header（导航）→ main（Hero、特色区、菜单区）→ footer（页脚），语义化标签自上而下；
  • 盒模型：点单按钮 padding、菜单卡片尺寸、border-box 保证宽度不被撑破；
  • 定位：导航 fixed 吸顶、购物车红角标 absolute 挂在图标上、回到顶部 fixed、z-index 分层；
  • Flex：导航三段对齐、3 张特色卡横排等高、自动换行；
  • Grid：产品菜单三列网格，招牌拿铁跨两列做大主推卡；
  • 响应式：桌面三列 → 平板两列 → 手机单列，vw/rem + 媒体查询；
  • 细节：8px 间距体系、字体三层级、统一圆角阴影、按钮 hover/active。

注意布局方案的选择逻辑：一维排列用 Flex、二维矩阵用 Grid、脱离常规层级用定位、普通上下堆叠交给文档流——没有银弹，只有对号入座。

二、黄金流程：先结构 → 再布局 → 后视觉

1. 定结构（骨架）：先不写任何样式，像晨光咖啡这样把页面分成导航、Hero、特色卡、菜单、页脚，用语义化标签搭好，理清主次内容。

2. 选布局（排布）：只解决"排得整齐、位置正确"——导航用 Flex、菜单用 Grid、角标用定位，此阶段不调颜色阴影。

3. 做适配（兼容）：移动端优先，配媒体查询和相对单位，保证手机不挤压、桌面不空洞。

4. 调细节（美化）：最后统一间距、字体层级、圆角阴影和交互反馈。

为什么不能反过来：边写边美化，一旦结构调整，样式全部返工；先把卡片调成粉色再发现它要从三列变单列，是新手最常踩的坑。

三、实战原则：先可读，后美观

  • 可读性：咖啡名、价格、描述层级分明，留白舒适；
  • 可用性：导航能跳转、按钮能点、三端都能用；
  • 美观度：统一的圆角阴影和反馈动效，服务于内容而非喧宾夺主。

没有结构和可读性支撑的美化，都是无效装饰。

四、结课

从一个点单按钮到一整间"晨光咖啡"，你学到的不是若干属性，而是一条完整链路：语义化结构 → 科学布局 → 响应式兜底 → 规范化细节。把店名换成书店、球鞋店、社团招新，用同一套流程就能独立做出新页面。

五、自学高频误区

  1. 上手就调色和阴影，结构没定，后期全部返工；
  2. 一个布局包打天下：简单按钮组硬套 Grid，复杂菜单硬凑 Flex；
  3. 只做桌面端，手机打开菜单横向溢出；
  4. 间距圆角随手写，六张卡片六个样；
  5. 特效堆满却忘了按钮没有 hover、角标层级被遮挡。
